# DESIGN.md

本文档记录 GitHub-Stars-AI-Tools 桌面应用的视觉系统与设计决策。

## 设计原则

1. **工作台优先**：首屏直接呈现核心功能，减少导航层级
2. **信息层次清晰**：用边框、留白、颜色深浅建立视觉层次
3. **克制使用颜色**：主色仅用于主要操作和状态指示
4. **一致的交互语言**：相同控件在不同位置保持相同外观和行为

## 色彩系统

### 语义色板

```css
/* 基础 */
--background: oklch(0.985 0.002 90);     /* 轻微暖灰底，舒适阅读 */
--foreground: oklch(0.18 0.008 90);      /* 深灰文字，4.5:1 对比度 */

/* 表面层 */
--card: oklch(1 0 0);                     /* 纯白卡片，清晰分层 */
--muted: oklch(0.97 0.005 90);            /* 弱化区域背景 */

/* 主色 */
--primary: oklch(0.48 0.14 240);          /* 知识蓝，专业可靠 */
--primary-foreground: oklch(0.99 0 0);

/* 次要色 */
--secondary: oklch(0.96 0.008 240);       /* 灰蓝，低调层次 */
--accent: oklch(0.95 0.02 240);           /* 强调色 */

/* 状态色 */
--success: oklch(0.55 0.15 145);          /* 柔和绿 */
--warning: oklch(0.68 0.16 75);           /* 琥珀 */
--destructive: oklch(0.58 0.22 25);       /* 柔和红 */
```

### 颜色使用规则

- **主色（蓝）**：主要操作按钮、选中状态、焦点指示、重要信息标记
- **次要色（灰蓝）**：次要按钮、Badge、标签
- **成功色（绿）**：完成状态、正向反馈
- **警告色（黄）**：待处理状态、注意提示
- **危险色（红）**：删除操作、错误提示

## 排版系统

### 字体

- **系统字体栈**：`-apple-system, BlinkMacSystemFont, "Segoe UI", "Noto Sans", Helvetica, Arial, sans-serif`
- **等宽字体**：用于代码、Gist ID、日期时间

### 字号层级

```
text-xs   11px   标签、辅助信息、时间戳
text-sm   13px   正文、表格内容、按钮文字
text-base 14px   卡片标题、输入框
```

### 字重

- **400 (normal)**：正文、描述
- **500 (medium)**：次要标题、强调文字
- **600 (semibold)**：区块标题、按钮
- **700 (bold)**：主标题

## 布局系统

### 网格结构

```
[280px 左侧边栏] | [minmax(620px, 1fr) 主内容区] | [400px 知识面板]
```

### 间距规范

- **xs**: 4px - 图标与文字间距
- **sm**: 8px - 小型元素内边距
- **md**: 12px - 标准间距
- **lg**: 16px - 区块间距
- **xl**: 24px - 大区块间距

### 圆角

- **按钮、输入框、选择器**: 8px (rounded-lg)
- **卡片**: 12px (rounded-xl)
- **头像**: 8px (rounded-lg)
- **标签芯片**: 8px (rounded-lg)

## 组件规范

### 按钮

**主要按钮**
- 背景：`--primary`
- 文字：`--primary-foreground`
- 圆角：8px
- 高度：40px (h-10)
- 阴影：`shadow-sm`
- Hover: 轻微上移 + 加深阴影

**次要按钮**
- 边框：`--border`
- 背景：透明
- 文字：`--foreground`
- Hover: 背景 `--muted`

### 输入框

- 高度：40px (h-10)
- 圆角：8px
- 边框：`--border`
- 背景：`--input`
- Focus: 2px 蓝色外框，阴影加深

### 徽章 (Badge)

- 圆角：8px
- 内边距：8px 12px
- 字号：12px
- 阴影：`shadow-sm`
- 变体：
  - `default`: 主色背景
  - `secondary`: 次要色背景
  - `outline`: 边框样式

### 标签芯片

- 最小高度：34px
- 圆角：8px
- 边框：1.5px
- 阴影：`shadow-xs`
- 选中状态：主色边框 + 10% 主色背景 + 外发光
- Hover: 上移 1px + 阴影加深

### 表格

- 表头：固定顶部，半透明背景，backdrop-blur
- 行高：保证触控友好（最小 44px）
- 选中行：淡蓝背景
- Hover: 淡灰背景
- 字号：13px (text-sm)

### 卡片

- 背景：`--card`
- 边框：`--border`
- 圆角：12px (rounded-xl)
- 阴影：`shadow-sm`
- Hover: `shadow-md`

## 交互状态

### 焦点

- 外框：2px solid `--ring`
- 偏移：2px
- 清晰可见，适配键盘导航

### 加载

- 旋转图标：`animate-spin`
- 骨架屏：`animate-pulse` + `--muted`
- 文字提示：动词 + "中…"（同步中…、抓取中…）

### 空状态

- 居中布局
- 图标：8x8 (32px)，`--muted-foreground`
- 标题：14px，600 字重
- 描述：13px，`--muted-foreground`
- 边框：虚线，`--border`
- 圆角：8px

### 禁用

- 不透明度：50%
- 鼠标样式：not-allowed
- 移除 Hover 效果

## 动效

### 过渡时长

- 快速：100ms - 颜色、不透明度
- 标准：150ms - 大多数交互
- 缓慢：200ms - 位移、缩放

### 缓动曲线

- `ease-out` - 交互反馈
- 禁用动效：`@media (prefers-reduced-motion: reduce)`

## 无障碍

- **对比度**：所有文字至少 4.5:1（正文）或 3:1（大标题）
- **焦点可见**：所有可交互元素提供清晰焦点指示
- **语义标签**：按钮、输入框、链接使用正确 ARIA 标签
- **键盘导航**：所有功能可通过键盘操作

## 文案与设置页写法

> 2026-10-22 起（GLM 起草，总控对着源码核对）。改任何界面文字、加任何设置项之前先读这一节。用词以 `docs/rebuild/文案审读.md` 里的「统一用词表」为准，这里不重复；已经发现的待改文案在同一份文件的「第二轮审读」里。

### 一个设置项由什么组成

必须有三项：

1. **名称**：名词，不带动词。用词表里的叫法（「每天额度」「自动整理」「AI 设置」），一个概念全应用只有一个名字。
2. **一行说明**：这个设置管什么，不超过 30 字。只说用户能感觉到的结果，不说实现（不写「表」「队列」「token 折算」）。
3. **当前值**：直接能读懂（「已开启」「20 万 token，约每天 33 个」）。不能只放一个开关，让用户自己回忆现在是什么状态。

看情况加五项：

4. **代价**：凡是会花钱、联网、下载的，必须写。顺序固定：先写「约整理 N 个」，token 放括号里；「具体花多少钱以你服务商的账单为准」照现有写法保留。
5. **去向**：数据发到哪、存在哪（AI 服务商、GitHub、钥匙串、本机文件夹），说清楚。
6. **后果与不包含**：改了会发生什么、不会发生什么。删除、覆盖类必须写「什么不受影响」，参照「清空本机数据」那段警告：动了什么、GitHub 上的收藏不受影响、建议先备份。
7. **状态词 + 下一步按钮**：状态不是终点，见下面的状态词表。
8. **默认值**：当前值和默认值不同才显示「默认：X」。

禁止：

- 应用自称「我来……」「我会……」；对用户说「您」。全程用「你」。
- 裸英文术语。token 只许出现在括号里；「README」第一次出现写成「项目说明（README）」。
- 一行说明里塞两个概念。
- 教用户把口令、密钥、令牌「发给别人」或「贴到网页、聊天里」。这类东西只许填进他信得过的本机程序。

### 写对了的样子（现有真实条目）

- **花钱的操作，把「会花钱」和「上限在哪」一起说**：顶栏快捷菜单里「给没有说明的收藏写中文说明」下面那行「会花钱，受「设置 → 自动整理与备份」里的每天额度限制」。
- **覆盖类操作，三件事齐全**：备份「恢复」的确认——会发生什么（当前资料库换成这一份）、已有的会怎样（先另存一份「恢复前自动留的」备份）、要不要重启（需要重启才生效），最后问「继续吗？」。
- **删除类操作，写清不受影响的**：「清空本机数据」的警告——动了什么、GitHub 上的收藏不受影响、先备份，一段话说全。

### 改写示范

| 毛病 | 原来 | 改成 |
|---|---|---|
| 自造了一个新名字 | 自动整理额度还剩 | 今天额度还剩 12 万 token（约还能整理 20 个） |
| 命令没说受什么限制 | 重新整理失败的 | 重试失败的整理（受每天额度限制） |
| 内部概念漏到界面 | 新版说明 N 个 · 旧版说明 N 个 | 中文说明已是最新 N 个 · 中文说明要更新 N 个 |
| 状态后面没有下一步 | 只显示最近 6 份，更早的在备份文件夹里。 | 只显示最近 6 份。要看更早的，点这里打开备份文件夹（旁边放一颗按钮） |
| 开发者单位 | 3 次，间隔 2000ms 起 | 3 次，间隔 2 秒起 |
| 花钱的开关旁什么都没写 | AI 精选：开 | 开关旁固定一行小字：开着时，每次搜索会请 AI 帮你挑（约 4 千 token，用「每天额度」里的一小份；每天额度没开时不会调用） |

### 状态词统一表

颜色只用「色彩系统」里已有的语义色：主色 `--primary`、次要色 `--secondary`、成功色 `--success`、警告色 `--warning`、危险色 `--destructive`。

| 状态词 | 意思 | 颜色 | 必须配的下一步 |
|---|---|---|---|
| 已开启 / 已关闭 | 开关的当前值 | 主色 / 次要色 | 不用配（开关就在旁边） |
| 已连接 | GitHub 令牌有效 | 成功色 | 「断开连接」 |
| 未连接 | 还没连 GitHub | 危险色 | 「去连接 GitHub」 |
| 还没配置 AI 服务 | 没法自动整理 | 危险色 | 「去设置 AI」（自动整理页已有这个按钮） |
| 待配置 | 通用：缺前置条件 | 警告色 | 指向对应设置页的按钮 |
| 暂停中 | 自动整理被手动暂停 | 警告色 | 「继续自动整理」 |
| 每天额度用完了 | 最近 24 小时额度用尽 | 警告色 | 「调高每天额度」 |
| 整理中 / 检查中 / 同步中 | 进行中 | 主色 | 长任务配「暂停」或「停止」 |
| 失败 N 个 | 整理任务失败 | 危险色 | 「重试失败的整理（受每天额度限制）」 |
| 连接失败 / 这次没连上 | 网络或服务不通 | 危险色 | 「再试一次」或「重新查」 |
| 已备份（上次备份：时间） | 备份完成 | 成功色或次要色 | 「现在备份」 |
| 都整理好了 | 待整理为 0（好消息，不是错误） | 成功色的语气 | 不用配 |

规矩：同一状态全应用只用一个词（有的地方「整理中」、有的地方「处理中」不行）；标签和按钮上的进行中写「动词 + 中…」（见「加载」一节），整句里可以写「正在整理 N 个」；状态词后面不接第二句技术解释，解释放在下一行的说明里。

### 改文案前的自查清单

1. 用词表里的词都对上了吗（工具、收藏、资料库、收集箱、中文说明、整理、每天自动整理、一次性全部整理、每天额度、交接单、同步、项目说明（README）、怎么试、令牌、密钥、钥匙串）？
2. 有没有裸露的英文术语？token 是不是在括号里、前面先说了「约整理 N 个」？
3. 花钱的操作：按钮或旁边一行有没有「会花钱 + 大约多少 + 上限在哪」？
4. 往外发的操作（上传备份、复制给 AI 助手）：发什么、发给谁、**不含什么**，都说了吗？
5. 写盘、覆盖、删除的操作：动了什么、什么不受影响、有没有二次确认？
6. 失败、空、暂停、未配置的状态：后面跟下一步按钮了吗？按钮文案就是按钮要做的事吗？
7. 按钮上的动词和实际执行的命令一致吗（对照 `invoke(...)` 的命令名再读一遍）？
8. 有没有超过 40 字的句子？超了就拆：先结论，后细节。
9. 语气：全程「你」，没有「您」，应用不自称「我来 / 我会」？
10. 状态词用的是上面那张表里的吗？颜色用的是语义色吗？
11. 要改的那一行是当场按原文搜到的吗（不要靠记忆里的行号）？
12. 前端靠子串判断后端报错文字的地方（例如「重新整理这一张」的失败提示靠「暂停」「还没配置 AI」决定要不要出「去自动整理」按钮），改了后端文字有没有同步改前端和测试？
