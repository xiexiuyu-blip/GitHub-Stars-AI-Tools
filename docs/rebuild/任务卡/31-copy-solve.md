# 卡 31 · 文案：找方案和「交给 Codex 的交接单」

## 为什么有这张卡
Fox（2026-10-05）：「现在很多文字描述还不是很合理」。总控让审读员站在他的角度读了全部界面文字（`docs/rebuild/文案审读.md`，49 条）。这张卡处理**找方案页和交给 Codex 的交接单**里的那些：同一份东西叫「参考包 / 任务交接 / 交接单」、理由句里是数据库字段名、两条规矩互相打架。

## Fox 能看到的效果
- 找方案右边的面板叫「**交接单**」，复制出去的文档标题是「# 交接单：把群聊记录整理成日报」。
- 每个结果下面的理由句变成大白话，例如：「对得上的地方：「群聊」→它能解决「需要把群聊记录归档成可读的文档」；「日报」→它能做「AI 总结生成 Markdown 日报」，项目说明里提到 9 次」。
- 列表顶部有「已替你勾了最对口的 N 个，不合适可以取消」；格式选项是「文档（Markdown，直接粘给 Codex，默认）/ 长期规则（AGENTS.md，存成文件放进工作文件夹）/ 程序用（JSON，一般不用选）」。
- 三个「直接交给 Codex」按钮统一成「不用这些工具，直接交给 Codex」。
- 交接单里不再自相矛盾：「装东西不用等我点头」后面带上「除了「开工前先问我」里点名要先问的」。

## 通用规则（三张文案卡都一样）
- **文案的依据是 `docs/rebuild/文案审读.md`**：每一条写了「位置、现在的文字、问题、建议改成」。本卡列出的条号逐条做；建议改成的文字照用，不要自己再润色成别的说法（觉得不妥写进报告，别改）。
- **统一用词表**（同一份文件里）一律照用：工具 / 收藏（GitHub 的 Star）/ 资料库 / 收集箱 / 中文说明 / 整理 / 场景 / 交接单 / 同步 / 项目说明（README）/ 怎么试 / 类型 / 令牌（GitHub）与密钥（AI 服务）/ 钥匙串 / 你（不自称「我」）。改完后，你改到的文件里不许再出现表里「要替换掉的旧叫法」（旧页面 `pages/dashboard|repositories|rankings|tag-network|ai-search|profile.tsx` 不在范围内，别碰）。
- **只改文字，以及本卡点名要修的行为**。不改布局、配色、状态逻辑、命令名、JSON 键名（后端的 camelCase 键、`PackRequest` 字段、`task.mode` 等契约一个字都不许动）。
