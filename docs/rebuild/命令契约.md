# 命令契约与协作规则

适用于所有 AI 开发者（Grok、Codex）和总控（Claude）。Fox 不需要读这份。2026-10-03 起生效。

## 1. 角色与顺序

| 谁 | 做什么 |
|---|---|
| Fox | 里程碑时亲手验收；只做只有他能做的事：输入电脑密码、钥匙串授权、粘贴令牌、批准 AI 试跑预算、点头切换正式库 |
| Claude（总控） | 写任务卡、建工作区、派发、审核、合并、向 Fox 汇报；Grok 做不了的、额度用完后剩下的，由 Claude 接手；最后一期收尾 |
| Grok（主力开发） | 按任务卡写代码和测试，交回报告 |

**Fox 定的顺序（2026-10-03）**：Grok 先开发，直到它本周额度用完；没开发完的由 Claude 接手；Grok 解决不了的问题，由 Claude 最后一期收尾。

## 2. Git 规则（Fox 2026-10-03 同意，只限本仓库）

- 只在本机：**不推送**、不改 remote、不打 tag、不开 PR。`origin` 指向 Fox 的 GitHub 分叉，也不要往里推。
- **两条线**：`fox-rebuild` 是 Fox 的开发版在跑的分支（主工作区），只在总控确认过的时间点更新（`tools/cards/release.sh`，一次发布只让开发版重新编译一次，也就只弹一次钥匙串授权）；`fox-integration` 是总控的集成线，每张卡审核通过后先合并到这里（在 `../fox-stars-lab-wt/_integration/` 里，用 `tools/cards/merge-card.sh`，任何一步失败都停下）。
- 每张任务卡一个分支 `card/<卡号-短名>`（基于 `fox-integration`），在独立工作区 `/Users/fox/WorkSpace/_external_tools/fox-stars-lab-wt/<卡号-短名>/` 开发（用 `tools/cards/new-card.sh` 建）。
- **只有总控能运行 git 写命令。** 开发者在工作区里只许 `git status|diff|log|show`。总控审核通过后在卡分支上提交，再 `git merge --no-ff` 合并进 `fox-rebuild`。提交信息以 `卡NN：` 开头，结尾带 `Co-Authored-By`。
- 合并后发现问题：`git revert -m 1 <合并提交>`，不改写历史（不 force，不 `reset --hard` 主线）。
- 主工作区（`fox-stars-lab/`）是 Fox 的 dev 版在跑的地方。**只有总控发布后它才会变**，没审核的代码不会出现在那里。

## 3. 一张卡的生命周期

1. 总控写卡 `docs/rebuild/任务卡/<卡号-短名>.md`（头部有「允许改动」清单，正文有「验收」），提交到主线。
2. `tools/cards/new-card.sh <卡号-短名>`：建分支和工作区。
3. `tools/cards/dispatch.sh <卡号-短名>`：后台派发给 Grok。三层保护：内核沙盒（只能写工作区；正式库、开发库、钥匙串和各类凭据读写都被内核禁止）、禁令清单（git 写命令、联网下载、杀进程、装依赖等被拦截，只返回错误，不会中止任务）、干净环境（不继承总控会话里的令牌和变量）。
4. Grok 交回 `.card-report.md`。
5. 总控审核（见 §7），先跑 `tools/cards/check-scope.sh <卡号-短名>` 核对改动是否都在卡里的「允许改动」内，越界的还原。通过：提交并合并。退回：写修改意见，`dispatch.sh <卡号-短名> <意见文件>` 续作。
6. 合并后总控在 Fox 的 dev 版里实际点一遍并截图，有问题就回退。
7. 一片（里程碑）做完，才请 Fox 亲手验收。

状态表在 `docs/rebuild/任务卡/README.md`。每次派发，总控都会告诉 Fox 派了什么、用的是 Grok 额度。

## 4. 允许的命令（在工作区根目录执行）

| 命令 | 作用 |
|---|---|
| `tools/cards/run.sh web-build` | 前端类型检查 + 打包（`pnpm build`） |
| `tools/cards/run.sh web-test [过滤词]` | 前端测试（vitest） |
| `tools/cards/run.sh rust-fmt` | 检查 Rust 格式（`--check`） |
| `tools/cards/run.sh rust-fmt-fix` | 自动整理 Rust 格式 |
| `tools/cards/run.sh rust-check` | Rust 编译检查 |
| `tools/cards/run.sh rust-test [测试名过滤]` | Rust 测试（`--lib`）。会跳过 1 个必须访问系统钥匙串的用例（沙盒里没有钥匙串，它必然失败），总控审核时在沙盒外跑完整套件 |
| `git status` / `git diff` / `git log` / `git show` | 只读 |
| 读文件、搜索 | 整个仓库；被沙盒禁止的位置读不到 |
| 写文件 | 沙盒只允许写工作区；逻辑上只许改任务卡「允许改动」里的路径，外加 `.card-report.md`，越界由总控事后核对并还原 |
| 普通文件和文本命令 | `mkdir`、`mv`、`cp`、`sed`、`find`、删除自己新建的单个文件等可以用 |

被禁止的命令（见 `AGENTS.md` 红线和 `tools/cards/dispatch.sh` 里的禁令清单）会被拦截并返回错误：换一种办法完成，不要想办法绕过。需要新依赖或新命令，写进报告。

## 5. 禁止的事

见 `AGENTS.md` 的「红线」，那里是唯一来源，这里不重复。

## 6. 交回报告格式（`.card-report.md`）

```markdown
# 交回报告 · 卡 <卡号-短名>

## 一句话结论
（做完了 / 部分完成 / 卡住了，一句话说明）

## 验收逐条
| 验收项（照抄任务卡） | 做到了吗（是/部分/否） | 证据（命令输出摘要，或 文件:行） |
|---|---|---|

## 改了哪些文件
- 路径：一句话说明

## 验证
- 命令 → 结果摘要（失败的也要写）

## 没做到的 / 偏离任务卡的地方
- 内容，以及原因

## 需要总控或 Fox 决定的事
- （没有就写「无」）

## 给审核者的提示
- 容易出错的地方、你不确定的地方
```

## 7. 总控怎么审（让开发者心里有数）

1. 读 diff：尤其盯卡外文件、被删的测试、被放宽的断言、写死的路径和密钥、新增依赖。
2. 在工作区自己重跑 `web-build`、`web-test`、`rust-fmt`、`rust-check`、`rust-test`，不信自述。
3. 对着验收逐条核对，每一条都要能指出代码位置或运行结果。
4. 涉及界面：合并后在 dev 版里点一遍并截图；涉及数据：在 dev 库副本上跑，不动 dev 库本体。
5. 涉及迁移：用 018 夹具和 dev 库副本各过一遍，确认只追加、不丢行。
6. 跑 `check-scope.sh`：越界改动一律还原，除非卡本身需要改（那就先改卡再合并）。
7. 任何一条过不去就退回，不凑合合并。

## 8. 额度

Grok 额度是 Fox 的。额度用尽时派发日志里会出现限额报错，总控据此停止派发并接手剩余工作，同时告诉 Fox。
