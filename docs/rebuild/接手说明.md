## 1. 安全边界（硬规则）

1. 不读、不改正式数据目录，除非 Fox **明确同意切换正式库**。
2. 不切换正式 bundle id，不打 tag，不开 PR，除非 Fox 明确要求。
3. `repositories` / `repo_ai_documents` / `repo_tags` / `annotations` 现有列不改名、不删除（web-search `stars` 在直接读）。
4. 密钥只走 Keychain。服务名：正式 `fox-stars-lab`，开发 `fox-stars-lab-dev`。不要打印、不要写入日志/进度/提交。
5. 本地 API 默认关；开启后只听 `127.0.0.1:39217`，除 `GET /v1/health` 外都要令牌，带 `Origin` 的请求一律拒绝。令牌存在 0600 权限的 `fox-stars-lab.local-api.json` 里，不要打印。
6. 启动开发版用：

```bash
cd /Users/fox/WorkSpace/_external_tools/fox-stars-lab
COREPACK_HOME="$PWD/.corepack" pnpm dev:desktop
```

不要用 `pnpm tauri dev`（那是正式身份，debug 会被拒绝）。

7. 每次动系统级路径前，确认本机是 Fox 的机器，且正式版 App 没在跑。本机 `/Applications` 里装着正式版 `Fox Stars Lab`，**不要启动它**。
8. 直接读 dev 库时，SQLite 只读模式在 WAL 下可能报 `unable to open database file`（缺 `-shm` 辅助文件）。要分析数据，先 `sqlite3 <库> ".backup '<副本>'"` 拷一份再查，别为此改库。

  - 本地 HTTP 接口：同时最多 16 个连接（满了回 503）、整个请求读取总时限 5 秒（原来只限每次读 2 秒，每 1.5 秒滴一行请求头能占一个连接几个小时）、写超时 5 秒；偶发的 accept 错误不再让监听线程永久退出（原来文件描述符一时用完就永远不监听了、界面却还显示「已开启」）；「监听中」看线程是不是还活着。
  - 审查员验过**没问题**的：本地接口的 Host / Origin / CORS 检查、收集专用令牌只能 `POST /v1/capture`（19 种方法 / 路径组合）、令牌随机性与常量时间比较、0600 权限、各种 URL 写法（userinfo、十进制 / 八进制 / 十六进制 IP、IDN、编码主机名）、重定向逐跳检查与固定 IP、请求头不带 cookie / Referer、`--max-filesize` 与解压后 16 MB 上限。
  - **没修的低优先级**：`StdResolver` 的 `getaddrinfo` 没有超时；响应头临时文件名可预测（`$TMPDIR` 是每用户目录，问题不大）；本地接口启用 / 轮换令牌的读改写没加锁；绑定端口失败只在状态里体现。
- **第二轮独立复核（审查员复核上面的修复，A1–A14）又找到并修了**（提交 dcc828d）：
  - **启动竞争（最重要）**：启动时嵌入维护线程和主线程几乎同时迁移同一个库，有待执行迁移时一边会失败（实测 12 次里 12 次）；失败的是主线程时，后台队列、额度闸门、本地接口都**悄悄没起来**，而且闸门还是「没装就放行」。现在迁移在进程内排队（`MIGRATION_LOCK`），额度闸门在起任何线程之前、只靠路径装上，没装上时旧功能一律拒绝（测试里除外）。
  - **旧账被「重新记到今天」**：认领 / 重试失败任务会把 `updated_at` 改成现在，几天前的用量跟着进了今天的窗口（20 条各 3 万的旧失败，重试一下就占掉 60 万，队列被锁）。现在认领和重试时先让超过 24 小时的旧用量归零，取消沿用原来的记账时间，恢复被打断的任务不再改 `updated_at`。**这对明天尤其重要**：队列里那批试跑时留下用量的积压任务，在窗口滑走之后被认领时不会再把旧账带回来。
  - 旧功能的「问额度 → 请求 → 记账」用一把可重入的锁串起来（两个请求同时问到「还有 10 万」、各花 6 万就是 12 万）；输出余量取 `max(3000, 输入)`；记账失败写日志、没有账号时报错；单次记账每列最多 500 万（服务商回离谱用量会让求和溢出、把队列锁 24 小时）；`usage` 解析改成宽松的（小数 / 字符串 / null 不再让整个回复解析失败）。

  - 读网页：`<3`、`a < b` 不再当标签；属性解析遇到 `@click` 之类跳过而不是停下；没结束的标签后面的整页丢掉（不再把 `<script>` / `<style>` 源码漏进摘要）；文章里提取仓库不受「聊天里最多 300 条链接」限制；任务列表不显示旧功能的账本行；测试临时库名加进程号和计数器（v2_ops 的测试曾因同名文件互相迁移而偶发失败）。
  - **仍未修、已知**：额度是本地记账，服务商那边真实计费看不到；一次尝试的预留 12k 不是绝对上限（CJK 很长的 README 加一次修复调用可能到 20k+，之后按真实用量补记，两条并发最多多出一两万）；远程嵌入调用不走这道闸（Fox 的嵌入是本地的）；`--noproxy '*'` 在「只能靠代理上网、没有 TUN」的网络里会让读取失败（Fox 是 TUN + fake-ip，没有代理环境变量，已核对）；`fetch_inbox_pending` 并发调用会重复读同一批 pending。

## 7. 已知坑

1. `reqwest` 访问 GitHub 可能 TLS handshake EOF；`rankings_live.rs` 已用系统 `curl` 回退。改榜单抓取时保留这条回退。
2. OSS Insight `/v1/trends/repos` 返回 `data_quality.status=unavailable`，不是空结果可当成功。
3. `list_capabilities` 为 0 是因为 `local_capability_entries` 本来空，不是查询坏了。
4. `get_graph_overview`（打开地图页）每次都会写库：补种子分类并跑一遍规则归类。已确认的分类以后要小心被它重复建议。
5. `v2_ops.rs` 里判断「已确认的卡」用的是对 `card_json` 文本做 `LIKE '%"review_status":"confirmed"%'`，JSON 一旦被格式化（多了空格）就失效；做确认功能时改成 `json_extract`。
6. Glass/Agents 里点 Markdown 文件链接可能卡死；给 Fox 路径时优先纯文本绝对路径，提醒用 Cmd+P 打开。
7. 回复 Fox 用简体中文。
8. computer-use 控制不了 dev 版：它是没有 bundle id 的裸可执行文件。看真实界面用 `tools/dev-ui/` 里的小工具（窗口截图 + 辅助功能接口按名称点按钮）。开发窗口被别的窗口完全盖住时 WebKit 会停止渲染，截图会是旧的，先把窗口挪到屏幕空白处。
10. **先读后写的写库事务一律用 `IMMEDIATE`**（`transaction_with_behavior(TransactionBehavior::Immediate)`）。默认的延迟事务先读（拿到读快照）再写，期间别的连接提交过，写入会立刻 `database is locked`，`busy_timeout` 对这种情况不起作用。在写卡（`persist_card`）上它会让「模型已经花了钱、结果没存下来、重试再花一次」。
11. 占位卡的三句固定废话：`想知道这个收藏是做什么的`、`查看项目说明`、`打开仓库 README`，来自 `v2_ops::import_summary_cards`（冻结，不要改）；读取侧统一用 `card_view.rs` 清洗，新增读卡的地方（列表、详情、找方案、参考包）都要走 `card_view::sanitize` / `display_one_liner`。
12. 开发库控制文件 `fox-stars-lab.queue.json` 的每日预算决定**所有** AI 花钱（队列后台整理 + 旧版的整批解析、单个仓库 AI 摘要、标签网络、AI 搜索、翻译、推荐）；`tools/cards/release.sh` 会拦。2026-10-04 起旧版功能也守这个额度（`spend_guard.rs`，守在 `ai.rs` 的四个对话请求函数上；做法和队列认领一样：在一个 `BEGIN IMMEDIATE` 里查「额度 0 / 队列暂停 / 24 小时已用 + 本次预计 > 额度」，通过就写一条 `running` 的预留行（job_type `problem_answer`、target_id `legacy-…`），队列认领看得见它；请求后换成真实用量，没记账就结束只留提示词那部分的估计，崩溃留下的由启动恢复记成已取消）；顶栏「增量 AI 解析」之前一点就是 160–190 万 token、没有取消，现在只会跑到额度为止。dev 设置里 `ai.enableAutoSummary` 是开的（Fox 决定不关）：它不会定时或启动时自己花钱，只在点了「抓取 README 并分析」之类的按钮后把抓取接到整批解析上，现在同样受额度管。连接测试和运行自检用 `spend_guard::probe` 包着：不看额度、不被暂停拦住，但照样记账。嵌入（向量）调用和列模型不走这道闸（本地嵌入不花钱，列模型不花 token）。
13. 用 `cargo test ... review_dump` 这种过滤词会把 `review_dump::review_server` 一起启动（它会一直阻塞）；跑夹具时测试名写全。
14. 后台（Rust）代码一重编译，dev 版二进制就变了，macOS 会弹「想使用钥匙串 fox-stars-lab-dev」，窗口卡在「正在加载本地配置…」，只有 Fox 能点「始终允许」。成批发布，发布前告诉他。
