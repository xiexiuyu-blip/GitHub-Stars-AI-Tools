```bash

COREPACK_HOME="$PWD/.corepack" pnpm dev:desktop
```

7. 每次动系统级路径前，确认本机是 Fox 的机器，且正式版 App 没在跑。本机 `/Applications` 里装着正式版 `Fox Stars Lab`，**不要启动它**。

## 4. 做到哪了：真可用 / 骨架 / 没做

### 真的可用

- 迁移器：版本号和名称都要匹配，迁移前自动备份并做完整性检查，每个迁移单独一个事务。有「空库 001→最新」和「合成的 018 库 → 最新，已有表行数不变」两个测试（旧的那个读真实 dev 库，库迁到 029 后永远过不了，已替换）。
- 开发库隔离：debug 或 dev 身份指向正式目录会直接退出，有测试。
- 备份：`VACUUM INTO` + 完整性检查。注意 `integrity_check` 只查结构不查内容；说明书要的 sha256 清单没做。
- 链接抽取（2026-10-02 重写，10 个测试）：URL 后面紧跟中文、全角标点不会再被吞进仓库名；`x.com/...` 这类没写 `https://` 的也认；GitHub 大小写、`.git`、`utm_*` 等跟踪参数、`twitter.com` 并入 `x.com` 后去重；`github.com/topics/...` 之类不算仓库；公众号长链接保留身份参数、丢掉 `pass_ticket` 等；本机和内网地址（含 `::ffff:127.0.0.1`、`100.64.0.0/10`）在预览时就标出来。
- 收集写库（同日重写）：整批一个事务，出错整批回滚；已在 Stars 里的仓库跳过；内网链接单独拦下，不中断其它；同一仓库换种写法再贴不会重复。
- 本地 API 加固（同日）：令牌、Host 与 Origin 校验、完整读取请求（正文可晚到）、每个连接一个线程；工具箱里可复制、重置令牌。
- 命令面板 ⌘K：搜仓库和分类，`?` 进找方案，`>` 执行命令。
- 资料库关键词搜索：单个关键词可用（「小红书」得 14 条）；**整句口语会得 0 条**（「做小红书封面的工具」）。
- 找方案：关键词明确的需求能给出像样的前 5 条（「做小红书封面」命中 5 条相关项目）。
- 设置页（上游）：GitHub、AI 引擎、**向量检索**、备份等分区都在。

## 5. 接手顺序（已与 Fox 确认，2026-10-02 夜）

**原则**：「完成」只能是 Fox 亲手用真实数据完成一件真实任务（见 Fox 的验收规则）。测试通过、页面能打开，都不算完成。界面动手前先给 Fox 可点击原型；每一片用「Fox 能亲手做的一件事」收口。

**第 0 步（已于 2026-10-02 夜完成）**
1. 本文与进度改写成真实状态。
2. 修失败的迁移测试（改用合成的 018 夹具，不再读真实 dev 库）。
3. 重写链接抽取与收集写库（见 §4）。
4. 本地 API 加令牌与来源校验。

**然后按四个闭环切片走**
1. **看懂**：（README 已于 2026-10-03 补齐）把理解卡流水线做进 App（真的消费 `ai_jobs`、分类清单进提示词、按 schema 校验、幂等、预算；同步后新 Star 自动出卡；写卡时同时填 `keywords_json`、`suggested_tags_json`，让 web-search 受益）；重做 84 张错分类卡和 92 张占位卡的分类；没有 README 时用描述加 topics 出低置信卡。注意 web-search 发现本地库比 GitHub 实时数据落后时会改用实时收藏（本机实测：本地 492 条，GitHub 494 条），所以**保持库新鲜（自动同步）本身就是给 AI 助手的价值**。
2. **找得到**：启用上游本地向量（设置页「向量检索」），资料库和找方案改调上游 `search_repositories` 的混合搜索；用现成的 40 条中英质量测试，加 Fox 提供的 10–15 个真实问题做评测。
3. **用起来**：找方案（LLM 重排、缺口、可选条目）；参考包（附录 E 模板、列表、用系统对话框保存到所选文件夹）；详情里补「设状态、复制给 AI、打开 GitHub、中文 README」。
4. **收得进**：收集箱界面；X 链接取正文（官方 oEmbed）；预览里直接标「已收藏 / 已在收集箱 / 将被拦下」。

**之后**：MCP 打包并在 Codex 里实跑；榜单换成真正的「新锐」来源并用向量算相关度；打磨与切换。

**说明书里建议划掉的**：连接器 runner、事件与 webhook、书签小工具、付费榜单源、拆 `storage.rs`/`lib.rs`、换状态库与路由。对「看懂、找得到、给 AI 用」没有可见收益。知识图谱（能力、问题节点）后放，先把检索闭环做准。「确认」不做成待办队列：AI 结果直接可用，用到它（加参考包、标想试或在用）就算认可，只留一个「不对」入口。
