Starcat 对照

对照报告 · 2026-10-19 · 第 4 版

Starcat 比我们强在哪，
我们能怎么改

Starcat 是你朋友做的成熟 Mac 应用（现已按 MIT 协议开源，你装的是 1.9.0 Pro）。这一页比两边都有的功能、它的全部 20 个设置页、它的AI 助手接入（CLI / MCP）和 RAG，还有产品完整度和文案：逐项打分，再说我们能怎么改。

这一版改了什么（你提的几处，我都补了）

  • 更正一个大判断（你指出来的）：我把「和收藏对话（RAG）」判成「不借、交给 Codex」，还把产品当成只会「复制给 Codex」，这是误解。知识库问答、仓库 AI 对话、AI 助手接入都要做，已经和 Starcat 好的部分一起排进后续计划，最新顺序见《进度与规划》。本页第 05、06、09、10 节按这个改了。
  • 我上一版把 MCP / 令牌判成「差不多」，判错了。它其实是一整套「AI 助手接入」：配对设备、一键复制配置、命令行、Skill。已改判「Starcat 更好」，单独一节：第 05 节。
  • 20 个设置页这次全比过了。上一版只细比了 8 页，另外 12 页被我当成「用不上」跳过了。现在：10 页 Starcat 更好、4 页差不多、6 页我们用不上（第 04 节总表）。
  • RAG 和本地工具单独成节（第 06 节）：它做的是「和收藏对话」，这一版已改判为要做；设置页的排法、状态牌和安全写法也值得借。顺带更正一处：我们藏着的向量检索面板其实是全的，缺的是接线。
  • 产品完整度、文案各一节（第 07 节、第 08 节）：差距主要在外围和「写法规范」，不在核心；单句文案我们并不差。

结论

Starcat 在「找得到、看得清、界面打磨」上更成熟；我们在「自动归到业务场景、中文理解卡、找方案交接单」上走了一条它没走的路；它有的「和收藏对话」「AI 助手接入」，我们也会做。

最该借的 4 样，都不花 AI 额度：维护状态标签 · 搜索排序与命中原因 · 整理进度看板 · 设计契约（DESIGN.md）。

设置页另有 7 处能借：设置搜索与分组 · AI 服务商（补 MiniMax / CC Switch 导入）· 「数据去哪了」一页 · 分档清理 · 快捷键一览 · 系统通知 · 实验功能区（第 04 节）。

这一版新增的重点：AI 助手接入，先做只读 MCP（第 05 节）· 把现成的向量检索面板接上线并写成白话，再加三档预设（第 06 节）· 设置页写法规范与文案盘点，由我来写（第 07、08 节）· 本机命令行当 AI 后端，先小试（第 06 节）。

第 4 版更正：知识库问答和仓库 AI 对话改判为「要做」，与 AI 助手接入一起排进后续计划，按「三个出口、一个检索核心」组织（第 10 节）。

一眼看区别 Starcat 更强的 7 处 其余 8 项 设置页 20 页 AI 助手接入 RAG 与本地工具 产品完整度 文案 各自独有 建议顺序

02

Starcat 比我们强的 7 处

每一处都写了：它怎么做、我们现在怎么样、我们怎么改。「不花 AI 额度」的意思是纯本地计算，不会动你的额度。

1

搜索：它会排序，还会说「为什么命中」

Starcat 更好

STARCAT

关键词 + 语义一起找，结果按相关度分 1–4 星；每条带一句命中原因；项目名字面命中的保底靠前；边输入边出结果。

我们现在

资料库只做「词匹配」：最多 4 个词，不排序，不说原因。本地语义搜索的代码有，但没启用（向量表是空的）。找方案走我们自己的打分，不受影响。
示意 · 改完之后搜索结果会这样（设计稿，不是现有界面）
小红书 封面
★★★★cover-maker命中：项目名 · 中文说明
★★★☆poster-skill命中：中文说明
★★☆☆image-prompt-kit命中：话题

怎么改

  • 先上全文索引和排序配方：项目名 > 中文说明 > 英文说明 > 话题；字面命中保底；最后一个词支持前缀。
  • 结果行加「命中：中文说明 / 话题 / 项目名」小标签（见上面的示意）。
  • 再启用本地语义搜索（接手说明里「找得到」那一步，本来就在计划里），和关键词混合排序。

STARCAT

Starcat 更好

STARCAT

03

其余 8 项共有功能

5 项差不多、3 项我们更好。这些先不动，只记下可借的小点。

差不多 5 项

同步 GitHub 收藏
STARCAT自动同步；用条件请求省 GitHub 配额；首次登录后台预热 README 和健康度，断了能接着做；同步 GitHub 的分组。
我们自动同步、可设间隔；失败自动重试、限流有提示；顶栏显示上次同步时间。
够用。「首次预热可恢复」的思路以后可借，优先级低。
筛选 · 排序 · 分组
STARCAT排序选项多；按语言、标签、仓库分组；「智能集合」预设视图（你那里有 8 个）。
我们按业务场景、使用状态、类型、有无中文说明筛；排序 3 种（收藏时间 / star / 最近更新）。
可借：智能集合。加几个预设视图：久未更新、想试没试、没有中文说明、最近收藏——免费、工作量小。我们的「业务场景」维度更贴你的用法，保留。
快速入口（收集 / 搜索）
STARCAT浏览器插件（在 GitHub 页面直接看笔记、标签、健康度）、Alfred / Raycast / uTools 搜本地仓库、Spotlight 系统搜索、菜单栏、桌面小组件——入口很多，围绕 GitHub 页面和系统本身。
我们从微信、公众号、X 文章里提取项目链接，进「收集箱」审核；有本地 API。全局快捷键 ⌥⌘F 的快速收集还没重建。
各有长处。它入口多，我们的收集来源它没有。⌥⌘F 值得补回来，其余入口优先级低。
额度与用量
STARCATAI 用量面板：请求数、Token、延迟、失败数，还有预估费用。另有免费的设备端本地小模型，不用 API Key。
我们24 小时滚动硬上限，默认 0，授权才花；档位写成「每天最多约 N 个收藏」，没有折成钱。
我们更稳，它更直观。可以在额度档位旁加一行「约 ¥x」小字（本地存一份价格表，免费、工作量小）。

我们的额度档位（示意数据）

导入 · 导出 · 备份
STARCATJSON 导入导出（兼容 OhMyStar / Astral）。多设备 iCloud 同步它自己也还没有（官方计划做成将来的 Pro 功能）。
我们导出 Markdown / CSV；自动本地备份，一键恢复。
够用，暂不动。你是单机使用。

我们更好 3 项

使用状态
STARCAT未读 / 阅读中 / 已采用 / 已废弃。
我们没看 / 想试 / 试过 / 在用 / 不要了；键盘 T / U / X 一键切换，操作带「撤销」。
我们更贴「要不要用」。它的「已采用 / 已废弃」基本对应我们的「在用 / 不要了」，我们多了「想试」「试过」两档，列表里一键切换。
分类与标签
STARCAT自己建标签、分组；AI 能批量给建议，你逐条审核；空标签库时还能先用话题在本地生成一套标签体系，不用配 AI。你的库里 541 / 542 还没打标签。
我们自动归到 13 个业务场景，再加形态（技能 / MCP / 命令行 / 应用……），不用你动手。
这是我们最大的差异。它的整理要你发起、逐条审核；后台自动整理要你自己去设置里打开（你这台没开）；我们是装好就自动归类。它「先在本地生成标签体系」的做法以后可借，用来补场景之外的自定义标签。
AI 说明
STARCATAI 摘要 + 标签建议 + 笔记草稿，由你发起（单个或多选批量，统一队列里审核）；后台自动整理也能做，要自己打开（你这台没开）；支持自带 Key，也有免费的设备端本地小模型。
我们中文理解卡（它能做什么 / 解决什么 / 怎么试 / 适合谁）批量自动生成，README 变了自动重做，有「说得对吗」确认和额度上限。
这是我们的核心，别丢。

这三项在我们的详情页一屏就能看到：场景标签（分类）、「我的状态」、中文说明区。（示意数据：这张没配 AI，所以说明区显示英文原文；你的真实库里约 500 个项目已有中文理解卡。）

① 配对

App 里生成一条 5 分钟内有效、只能用一次的配对命令；粘到目标终端回车，再回 App 点确认。按它的设计文档，之后每台设备一个独立令牌，可单独撤销，存在系统钥匙串里。

App 是唯一入口

③ 命令行 starcat

给终端和脚本用

配对、体检、搜仓库、取上下文、记笔记、打标签……同一套能力的转接头，不另写一份逻辑。写操作默认预演，加 --apply 才真改。

④ Skill

一份「怎么用」的说明

starcat-skill 只放使用说明，让 Codex / Claude Code 知道什么时候该调用、怎么调用。不含任何凭据。

它是一个完整的产品；我们现在是两个要手抄的令牌

Starcat 更好

STARCAT

设置 → MCP 一页走完：配对设备 → 安装 MCP Service → 安装 starcat-skill。每一行右边一个「复制」键，Claude Code 给 JSON、Codex 给 TOML；写入权限分档，默认全关。MCP 服务仅 Pro 用户可用（你是最高订阅）。页脚写明：只监听 127.0.0.1，并要求使用共享的本地 API Key。

它做对的 4 件事（可以照着学）

  • 每一步都有「AI Agent · …」：复制一句话交给 Codex / Claude Code，让它自己配、自己验证；想自己动手的，旁边还有「目标设备终端 · …」「Claude Code · …」「Codex · …」。不爱敲命令的人也能接上，对你特别合适。

  • 写明「不要做什么」：「不要添加 endpoint 或 Local API Key」「安装说明不包含长期凭据。请只配对可信设备，并核对 Starcat 显示的确认信息。」
  • 按客户端给格式：Claude Code 一份 JSON，Codex 一份 TOML，不让人自己改格式。

我的建议：值得做，分三步，先只读

  • 第一步（先做）：设置里加「给 AI 助手用」：三个复制键（Codex 配置 · Claude Code 配置 · 让 AI 帮我配），默认关。先开放 4 个只读能力：搜资料库、取某个项目的中文理解卡、列业务场景、取交接参考包。Codex 就不用你再手动复制了。
  • 顺手做 Skill：一份很短的说明，教 Codex 什么时候该查你的收藏。几乎零成本。
  • 第二步：配对码 + 每台设备单独的令牌，换掉现在手抄的两个长期令牌（可单独撤销）。
  • 第三步（可选）：写入类（改「想试 / 在用」、加标签），一律预演 + 审计，只由 App 写库，顺便解决 log_usage 绕过 App 的老问题。
  • 命令行先不做：本地 API 和 MCP 已够用，多一套要维护；以后要，就做成 MCP 的转接头。
不花 AI 额度工作量：第一步 中要你点头：做不做、做到哪一步
