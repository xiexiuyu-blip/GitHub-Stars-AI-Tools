# 微信工作台接入 Stars Lab 收集箱

写给微信工作台的开发者。这个接口只在本机、默认关闭。Stars Lab 没开，或工具箱里没打开本地 API 时，请求会被拒绝。

## 怎么开、地址、令牌

Fox 在 Stars Lab 的工具箱里打开本地 API。地址固定是 `http://127.0.0.1:39217`，只听本机，不要改成局域网地址。

令牌由 Fox 在工具箱复制「收集专用令牌」，粘进微信工作台的设置。工作台不要去读 Stars Lab 的数据目录或控制文件。这把令牌只能调用下面的收集接口，拿它访问别的接口会得到 403，读不到资料库。

令牌泄露了，让 Fox 在工具箱点「重置」。旧令牌马上失效。重置这一把不影响另一把完整令牌。不要把令牌写进日志、崩溃报告或群聊。

每个请求都要带 `Host: 127.0.0.1:39217`（`localhost:39217` 也可以）。不要带 `Origin` 头，带了会被拒绝。响应没有 CORS 头。

## 请求

`POST /v1/capture`，`Content-Type: application/json`，`Authorization: Bearer <收集专用令牌>`。

```bash
curl -sS 'http://127.0.0.1:39217/v1/capture' \
  -H 'Host: 127.0.0.1:39217' \
  -H 'Authorization: Bearer <收集专用令牌>' \
  -H 'Content-Type: application/json' \
  --data '{"text":"看看这个 https://github.com/owner/name","urls":["https://github.com/owner/name"],"sourcePlatform":"wechat","sourceContext":"群：小红书运营交流 · 张三 · 2026-10-04 09:30"}'
```

| 字段 | 说明 |
|---|---|
| `text` | 群里原话。最多 50000 个字符。和 `urls` 至少有一个非空。会存成条目的原话（去掉首尾空白，最多 2000 个字符） |
| `urls` | 链接数组，最多 100 条，每条最多 2048 个字符。和 `text` 合成时 `urls` 在前、`text` 在后，中间空一行 |
| `sourcePlatform` | 消息从哪来。微信用 `wechat`。允许 `web`、`github`、`x`、`wechat`、`telegram`、`discord`、`forum`、`xiaohongshu`、`bilibili`、`youtube`、`local`、`other`。别的值按 `other` 记，不报错。缺省是 `other` |
| `sourceContext` | 建议写成「群名 · 发送人 · 时间」。最多 2000 个字符，超出截断，不报错 |

`text` 和 `urls` 都空时返回 400，消息是「没有可收集的内容」。整个请求体还有 64KB 上限，超了是 413（和上面的字数限制同时生效）。

## 响应

成功是 200，没找到链接也是 200（`linksFound` 为 0），不是错误。

```json
{"ok":true,"created":1,"skipped":0,"duplicateBatch":false,"alreadyStarred":0,"alreadyInInbox":0,"blocked":0,"linksFound":1}
```

| 字段 | 说明 |
|---|---|
| `created` | 新放进收集箱的条数 |
| `skipped` | 没新建的条数（已收藏 + 已在收集箱 + 被拦住） |
| `duplicateBatch` | 同一段文字已经收过 |
| `alreadyStarred` | 已经在 Stars 里的 GitHub 仓库，不再收 |
| `alreadyInInbox` | 收集箱里已经有的链接 |
| `blocked` | 本机或内网地址，单独拦住 |
| `linksFound` | 识别出的链接数 |

## 错误

| 状态 | 什么时候 |
|---|---|
| 400 | 正文不是 JSON、字段类型不对、没有可收集的内容、链接超过 100 条、单条链接超过 2048 个字符、原文超过 50000 个字符 |
| 401 | 没带令牌，或令牌不对 |
| 403 | 本地 API 没开；`Host` 不对；带了 `Origin`；收集专用令牌用在了别的接口 |
| 413 | 请求体超过 64KB |
| 415 | 没有 `Content-Type: application/json` |
| 500 | 写入失败。响应只有「收集写入失败」，没有内部原因 |

## 幂等和建议

同一段文字再发一次，返回 200，且 `duplicateBatch` 为 `true`，不会重复收。去重看的是合成后的整段（`urls` 在前、空行、`text` 在后）的哈希，`sourceContext` 不参与。换一种说法或改了链接，才会另收一批。

一次请求只发一条消息。只发含链接的消息。`sourceContext` 写成「群名 · 发送人 · 时间」。不要发聊天全文，也不要发手机号等隐私。
