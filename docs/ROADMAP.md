# Fox Stars Lab 开发路线图（唯一现行版本）

> 本文档取代仓库早期 `docs/archive/v1/` 中的路线图与 `docs/rebuild/后续开发计划.md`（10 月草案），并吸收前期产品与体验评审中尚未落地的核心建议，作为 **`2.1.0-fox.1` 之后**的唯一演进计划。

---

## 一、已交付基线（已完成，不重复排期）

- **2.0 重建基线（迁移 019–036）**：应用身份隔离、正式库安全切换、AI 任务队列与预算闸门、`card-v3` 中文理解卡、业务场景规则归类、今日/资料库/找方案/收集箱四大闭环、三格式交接单与本机 HTTP API。
- **2.0.0-fox.2（批次 A，迁移 037–038）**：交接单版本一致与防并发覆盖、离开返回保留草稿、单张带授权重写、顶部搜索全键盘操作、README 更新缓存失效、找方案维护状态提醒、20 项隔离 E2E 与发布门禁演练。
- **2.1.0-fox.1（M1–M5 升级，迁移 039）**：删除 10 个淘汰/不可达旧页、合并重做为单层 6 页签设置、接入近 50 次成功样本动态 token 估算、发现工作台升级为三模式（热门趋势 5 路榜 / 自由搜索 / 按场景补缺近 90 天新锐）、UI 去个人化与文案审读问题清零、支持列表上下键与资料库切页状态保留。

## 二、后续演进规划（P1 → P3）

总体架构遵循 **“一个检索核心，三个产品出口”**：资料库找得到、应用内直接问答（RAG）、外部 AI 助手按需取资料（MCP/CLI）共用同一套带命中证据的检索与维护状态契约。

### P1 · 检索核心与 AI 助手只读接入（优先度最高，核心链路零对话费用）

| 能力项 | 具体目标与验收标准 |
|---|---|
| **1. 检索排序升级与本地混合语义检索上线** | 接通后端已预留的 `embedding.rs` / `vector_index.rs`（本机 e5 多语模型 + zvec/SQLite）；补充中英文混合检索融合排序与明确命中原因（「名称命中 / 说明命中 / 意思相近」）；使用 `docs/quality/embedding-golden.json` 与真实任务句对照评测，要求**精确项目名不退步，语义改述有可解释改善**；未下载模型或离线时平滑降级为纯关键词检索。 |
| **2. 白话化的语义设置与真实状态反馈** | 将原隐藏的向量配置重构进「设置」单层结构，使用户能看懂模型未下载 / 下载中 / 索引中 / 部分可用 / 过期等真实状态，独立勾选要参与本地索引的来源（说明卡 / README 摘录 / 笔记），并明确区分“本机可检索”与“允许发往外部 AI”。 |
| **3. 智能集合预设视图** | 在资料库增加零费用预设筛选项：如「久未更新」「想试没试」「待补充中文说明」「最近收藏」。 |
| **4. 外部 AI 助手只读接入（MCP + 配置复制 + Skill）** | 在 `local_api.rs` 扩展只读查询路由并记录本机审计日志；打包轻量只读 MCP stdio 桥接器（仅通过本地 API 访问，不直接读写 SQLite）；在「设置 → 外部连接」提供总开关、审计记录、Claude Code / Codex 配置一键复制与配套 Skill 模板；默认不向外部助手开放个人私密笔记。 |

### P2 · 应用内收藏问答（RAG）与选型闭环（需用户主动授权独立额度）

| 能力项 | 具体目标与验收标准 |
|---|---|
| **1. 资料库级问答与详情页「问问它」** | 不新增主导航项，将问答入口融入「资料库」顶部（回答“我收藏里有哪些能做 X / 对比 Y 与 Z”）及详情页「问问它」页签；检索免费召回有限证据片段后单次调用 AI，严格校验引用出处存在于检索集合且内容支撑结论。 |
| **2. 独立日额度与不可用时强制降级** | 问答使用独立于后台自动整理的日额度通道；未配置 AI、额度为 `0` 或耗尽时，界面不锁死，直接返回本机命中的候选列表与命中原因，并允许一键转交外部 AI 助手继续追问。 |
| **3. 说明可追溯、定向纠错与轻量对比** | 详情页区分项目更新、README 抓取与 AI 整理时间，支持展开对应证据片段；纠错时可选具体原因（用途不对 / 安装过时 / 场景不对）再决定是否重写；支持选 2–3 个候选做轻量对比与记录用后一句话备注（“用来做了什么 / 为什么放弃”）。 |
| **4. 发现与收集到资料库的最短回路** | 保留「以 GitHub Star 为正式收藏源」的清晰边界，打通从发现/收集到去 GitHub 加星、同步后直达资料库或返回原找方案任务的闭环引导，避免状态模糊。 |

### P3 · 助手进阶、体验精修与跨平台交付

| 能力项 | 具体目标与验收标准 |
|---|---|
| **1. AI 助手安全写入与设备配对** | 新增写入类工具（改阅读状态、写备注、投递收集链接等），强制默认 `dry-run` 预演 + App 内首次确认 + 完整审计；用一次性短期配对码与每设备可撤销令牌替代手抄长期令牌。 |
| **2. 日常体验与效率小件** | 整理进度与状态漏斗小看板；详情页按需手动翻译 README 并本地缓存；对「想试 / 在用」项目提供只读 Release 新版提醒；找回全局快速收集快捷键；补充人民币估算参考（标明以服务商账单为准）与更多开箱即用 AI 预设。 |
| **3. 跨平台 CI 与发版对齐** | 对齐 `.github/workflows/release.yml` 中的旧产品名（从 `GitHub-Stars-AI-Tools` 迁移到 `Fox Stars Lab` 产物规范）、补齐 Windows / macOS Intel / Apple Silicon 构建与签名及独立 `latest.json` 更新源验证。 |

## 三、长期演进原则（Do & Don't）

- **控制信息密度**：保持主导航不超过现有 5 大工作台 + 设置的结构，新能力优先收进现有工作台内，不额外堆砌孤立页面。
- **有代价必先声明、不可用必有降级**：任何会联网、写盘、下载模型或花费额度的动作都在执行前讲清边界，且不能因为缺少 AI 额度卡死核心本地工作流。
- **严守安全与可逆边界**：外部网页、README 与仓库内容永远视作不可信输入；数据库迁移继续保持追加与迁移前自动备份。
- **暂不纳入范围**：多用户云端账号体系、团队协同权限后台、服务端托管公共榜单、AI 提示词自由编辑器与内置商业付费系统。
