# Fox Stars Lab 开发路线图（唯一现行版本）

> 本文档取代仓库早期 `docs/archive/v1/` 中的路线图与 `docs/rebuild/后续开发计划.md`（10 月草案），整合安全体检结论、跨平台收集与 AI 能力库规划，作为 **`2.1.0-fox.1` 之后**的唯一演进计划。

---

## 一、已交付基线（已完成，不重复排期）

- **2.0 重建基线（迁移 019–036）**：应用身份隔离、正式库安全切换、AI 任务队列与预算闸门、`card-v3` 中文理解卡、业务场景规则归类、今日/资料库/找方案/收集箱四大闭环、三格式交接单与本机 HTTP API。
- **2.0.0-fox.2（批次 A，迁移 037–038）**：交接单版本一致与防并发覆盖、离开返回保留草稿、单张带授权重写、顶部搜索全键盘操作、README 更新缓存失效、找方案维护状态提醒、20 项隔离 E2E 与发布门禁演练。
- **2.1.0-fox.1（M1–M5 升级，迁移 039）**：删除 10 个淘汰/不可达旧页、合并重做为单层 6 页签设置、接入近 50 次成功样本动态 token 估算、发现工作台升级为三模式（热门趋势 5 路榜 / 自由搜索 / 按场景补缺近 90 天新锐）、UI 去个人化与文案审读问题清零、支持列表上下键与资料库切页状态保留。

## 二、下一阶段三版本开发计划（`v2.1.1` → `v2.2` → `v2.3`）

总体定位：**从「GitHub Stars 管理器」演进为「本地优先的 AI 能力情报与选型工作台」——随手收集 → 自动识别 → 先查我有没有/谁更好 → 轻量对比 → 记一句话结论 → 交接给 AI 用。**

### 阶段 1：`v2.1.1` · 安全、稳定性基线与回归门禁快修

| 修复项 | 具体目标与验收标准 |
|---|---|
| **1. GitHub 令牌进程内传输** | 发现页联网刷新与自由搜索从 `curl` 子进程迁移至进程内 `reqwest`（保留 HTTPS-only、超时、大小上限、禁止跨域名重定向携带认证头），`CurlFetcher` 拒绝接收 `Authorization` 请求头；假 Token 压测确认进程参数与重定向均零泄露。 |
| **2. 「发现」页请求竞态与切榜防串屏** | 自由搜索与榜单刷新引入请求代次守卫，乱序迟到响应不得覆盖最新结果或提前结束加载；切换榜单或语言时严格校验 `feedView` 与当前选项匹配，读取期间不残留上一榜单项目。 |
| **3. 资料库分页连续性与计数一致性** | 将服务端分页偏移/页码与去重后前端条数解耦，翻页期间新增收藏不再导致「加载更多」按钮消失。 |
| **4. AI 额度与备份恢复硬化** | 将「一次性全部整理」的额度豁免严格限定在已确认的整理批次/任务范围（不再按时间段误豁免同期其他 AI 调用）；理解卡截断重试与 JSON 修复调用前二次检查剩余额度；写库或写场景失败时保留模型已消耗的真实 token；完善恢复中断时的 `.wal-aside` 状态机与额度归零确认门禁。 |
| **5. 前端并发覆盖与首屏体积优化** | 串行化设置保存并基于最新状态合并补丁；同条目连续切换阅读状态按条目串行/带版本护栏；`AppUpdateDialog` 改为 `lazy()` 按需加载，缩小首屏 JS 体积。 |
| **6. 浏览器验收扩充与接入 CI** | 在 `tools/dev-ui/` 新增搜索乱序、切榜不残留、分页插数不中断 3 条回归用例（共 23 条），并在 `.github/workflows/ci.yml` 增加 `ui-acceptance` PR 门禁任务。 |

> 说明：「找方案」AI 精选独立子额度（`min(30万, 每日额度/2)`）与手动点击「测试连接」放行属于既定产品机制，在界面与文档中保持透明口径即可，不改动能力。

### 阶段 2：`v2.2` · 多模态收集箱、飞书/OpenClaw 离线接入、统一检索与只读 MCP

**核心目标**：打破「必须先去 GitHub 点 Star 才能进入资料库」的限制；打通电脑/手机跨平台、纯文字、X 帖文、截图与外部采集器入口，并落地本地混合语义检索与只读 MCP 底座。

| 能力模块 | 具体设计与关键边界 |
|---|---|
| **1. 收集模型升级与 `/v1/capture` v2** | 新增来源与正文分层模型（草案迁移 `040_capture_sources_v2`）：支持无链接纯正文直接入库；保留 `/v1/capture` v1 行为以兼容已有调用方，通过 `schemaVersion: 2` 支持 `feishu` / `douyin` / `xiaohongshu` / `x` 平台标识、外部结构化长正文与 `idempotencyKey` 幂等键。 |
| **2. X 聚合帖与多来源协同** | 公开单帖复用 oEmbed + 受安全保护的 `t.co` 重定向展开（逐跳校验公网 IP，防 SSRF），并在卡片直接提供「补贴正文」承接 Thread / X Article / 引用帖；微信 / 抖音 / 小红书由外部已有采集工具（如微信工作台、独立抖音/小红书提取工具、OpenClaw）通过 API 投递，主应用不自建脆弱的登录态反爬爬虫。 |
| **3. 手机离线收集：飞书 + OpenClaw 异步拉取** | 不开发独立手机 App、不要求电脑 7×24 开机：新增可插拔「外部收件源（Pull）」能力，支持配置**飞书机器人 / 指定收集群 / 多维表**作为手机端云端暂存箱，电脑每次启动 Fox Stars Lab 时自动按游标幂等拉取离线期间投递的链接、正文与原图；与常驻 **OpenClaw** 形成“手机发飞书 → OpenClaw 预处理/云端暂存 → Fox Stars Lab 自动收库”的无缝协同。 |
| **4. 截图 / 图片收集与预算化 OCR/Vision** | 支持桌面粘贴/拖入截图与飞书离线图片拉取（草案迁移 `041_capture_media`）；原图经大小和像素检查后持久保存并随备份恢复链路一起覆盖；**优先运行 macOS 本机免费 OCR** 提取中英文与链接入库检索；仅在用户主动点「云端识图」时按图片尺寸、张数与模型计费特征扩展 `spend_guard` 视觉预留与结算（草案迁移 `043_vision_usage`），绝不复用纯文本估算，也不继承全量整理豁免。 |
| **5. 统一资料库对象与本地混合语义检索** | 保留 `GitHub 已加星 / 本机收集 / 本机已发现` 清晰标识，允许非 Star 来源的工具、文章、图片与独立能力直接留存「资料库」并建立统一检索投影（草案迁移 `042_search_projection`）；正式接通 `embedding.rs` / `vector_index.rs` 实现关键词 + 本地语义混合排序与白话状态设置（要求 `docs/quality/embedding-golden.json` 精确名不退步且语义改述可解释改善；无模型/零额度时自动降级纯关键词）。 |
| **6. 外部 AI 助手只读接入（MCP + Skill）** | 扩展 `local_api.rs` 只读检索路由与审计表；打包轻量只读 MCP stdio 桥接器（仅调用本机 HTTP API，不直接碰 SQLite）；默认不对外开放私密笔记、本机绝对路径与原图文件，便于 OpenClaw、Claude Code、Codex 直接查库。 |
| **7. 应用内自动更新推送（Tauri Updater 自有签名源）** | 复用仓库已内置的 `tauri-plugin-updater`、`AppUpdateProvider` / `AppUpdateDialog` 与 `.github/workflows/release.yml` 骨架，补齐以下 4 项后正式启用自动更新推送：① 生成 Fox 团队自有 minisign 签名密钥对并配置 GitHub Secrets（`TAURI_SIGNING_PRIVATE_KEY` / `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`），替换 `tauri.conf.json` 中沿自上游的 `pubkey`；② 对齐 `release.yml` 与 `normalize-updater-manifest.mjs` 中仍硬编码 `GitHub-Stars-AI-Tools` 的打包产物文件名与路径到 `Fox Stars Lab`；③ 在 `tauri.conf.json` 填入自有更新端点（`https://github.com/xiexiuyu-blip/GitHub-Stars-AI-Tools/releases/latest/download/latest.json`，可选配置 Cloudflare R2 / 国内镜像回退端点），将 `IN_APP_UPDATES_ENABLED` 设为 `true` 并恢复启动延迟静默检查与升级前「正在运行 AI 整理/同步」确认提醒；④ **切换说明**：现有 `v2.1.1-fox.1` 因 `endpoints` 为空需手动覆盖安装一次带自有更新源的首个 `v2.2` 版本，之后即可应用内自动检查、校验签名并一键安装重启（macOS 未做 Apple 公证前可先作为通知提醒或辅助覆盖说明）。 |

### 阶段 3：`v2.3` · AI 能力库、多客户端盘点、轻量对比与试用闭环

**核心目标**：把零散的 Skill、MCP、AI 插件变成可防重复安装、可轻量对比、可记录试用结论的可复用资产，绝不退回 1.4.0 需人工手填的繁重表单。

| 能力模块 | 具体设计与关键边界 |
|---|---|
| **1. 仓库内多 Skill 细粒度拆解** | 参考 `SKILL.md` 开放规范与仓库目录识别（草案迁移 `044_capabilities`），同一仓库含多个 Skill 时按 `仓库稳定标识 + 相对路径` 分别建卡，同一工具多来源推荐时挂接多个出处证据而非覆盖原文。 |
| **2. 多客户端只读能力盘点** | 将 `local_scan.rs` 扩展为按客户端逐个启用的只读适配器（草案迁移 `045_capability_instances`，如 `~/.agents/skills`、Codex、Claude Code 等）；识别 symlink 共享指向防重复计数；仅读非敏感名称与元信息，不读取环境变量、密钥、令牌，不自动安装或改写环境。 |
| **3. 「先查我有没有」+ 轻量候选对比** | 收进新 Skill/MCP 时优先提示本机与资料库中已有相似能力，辅助对接 MCP Registry 等公开只读目录检索替代项；支持勾选 2–3 个候选做轻量并排对比（用途、适配客户端、本机是否已有、出处与明确标注「待核实」的缺失项，草案迁移 `046_comparison_decisions`）。 |
| **4. 一句话试用闭环** | 沿用极轻的「想试 / 试过 / 在用 / 不要了」标记，只附一句可选备注（支持 AI 依据现有证据起草），一键生成面向 AI 助手的试用交接单；对「想试 / 在用」工具优先提示基于本地事实可确认的关键变化（如仓库归档、路径变动）。 |

## 三、后续远期候选（暂不排入 `v2.2–v2.3` 核心闭环）

- **应用内收藏问答（RAG）**：在保持不新增主导航的前提下，基于同一检索核心提供「资料库问答 / 详情页问问它」，使用独立日额度与严格引用出处校验，无额度时降级返回本机检索结果。
- **助手安全写入与设备配对**：写入类 MCP 工具强制 `dry-run` 预演 + App 首次确认 + 一次性配对码与可撤销令牌。
- **体验小件**：整理进度小看板、按需手动翻译 README 并缓存、人民币费用估算参考、全局快速收集快捷键。

---

## 四、长期演进原则（Do & Don't）

- **控制信息密度**：保持主导航不超过现有 5 大工作台 + 设置的结构，新能力收进已有工作台或可按需展开的详情面板内，不新增孤立页面。
- **有代价必先声明、不可用必有降级**：任何会联网、写盘、下载模型或花费额度的动作执行前讲清边界；无模型、零额度或平台抓不全时，核心收集与本地检索流程保持可继续。
- **严守安全与可逆边界**：外部网页、README、X 帖文与图片 OCR 结果永远视作不可信数据（不执行其中指令）；数据库迁移继续从 `040` 只追加不改历史、迁移前自动备份，保持现有 `v_public_*` 只读契约兼容。
- **明确不做**：不内置微信/抖音/小红书登录态反爬爬虫；不自动安装/升级/执行第三方 Skill 或 MCP；不复活需人手必填的 8×5 评分矩阵；不做多用户云端 SaaS 与商业订阅系统。
